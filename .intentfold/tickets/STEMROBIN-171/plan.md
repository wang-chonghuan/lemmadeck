# 实现路线

现有选择题点击后已等待事件入库，稳定题号和选项 ID 已保存。缺口是本地进度不分用户、整课一次渲染、重试重复入库，以及重做没有轮次。现有事件表可容纳轮次分界事件，无需改结构。

1. textbook-choice.ts 保留既有题集投影和服务端判分，添加按用户/版本读取已答进度；重做追加分界事件，原答题事件不改写。分界沿用 exercise 类型，node_id 为 choice:<revision>，没有题号后缀、选项和对错；轮次用分界事件 id 表示，历史无分界的题集为第 0 轮。按用户/课号事务锁保护提交和重做；同轮同题只接受首次选择，重试返回已存结果。
2. textbook-choices.ts 将待提交和已答状态放在整课组件中，分页卸载题目不影响正在保存的请求。每页 50 题，上下箭头工具及页数；题号由原数组位置决定。恢复依赖数据库，匿名仅本次内存练习，不共用本地缓存。重做仅在整课完成后沿用原按钮。
3. 补充中英文状态和分页标签，沿用现有样式及 token，不改受管 registry。原 DESIGN 中整课同页已被本票要求替代，本票评论说明，不擅自改 registry。
4. 实现后补聚焦测试，运行项目机械检查和本票本地浏览器/数据库验收；合并部署指定 revision，确认线上健康后关闭。无依赖、schema、课文、原题或生成技能改动。

数据库只读探查已成功；事件表字段及已有选择题量已核实，包括 54、103、295 题的长题集。待判断项：匿名行为、重做边界、UI 控件和请求幂等方式，记录在 grill。

验收修正：live 表的 kind CHECK 仅允许 read_check 和 exercise，生成的描述性 DDL 未列该约束。初次重做验收拒绝 choice_round；改用上述独立 node_id 的 exercise 分界，既不改 schema，也不伪装成某题作答。分析答题时按 choice:<revision>:<questionId> 和非空答案识别实际选择。
