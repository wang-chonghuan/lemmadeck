# 开发前判断

用户明确授权 self，不再向用户提问。依据 live 工单、四份 Charter、现有组件与数据库只读实况。

1. 是否另建答题日志或修改结构？
   推荐：否，复用既有事件表，以 choice_round 事件分界轮次；答题字段与格式保持不变。
   理由：现有 user/lesson/kind/node/answer/time 和自增 id 已足够，追加标记可区分重做。
   决策：按推荐执行，自行判断；已实查字段及数据库可连接，未跨 schema/依赖红线。
2. 提交失败/翻页及重复请求如何处理？
   推荐：请求状态由整课组件持有；同轮同题首次选择锁定，事务内读取已有结果后插入；重做与提交共享同用户/课号短事务锁。
   理由：现有每题首次回答后锁定，无需引入后台队列、重试系统或第二日志。
   决策：按推荐执行，自行判断；保留既有首次选择锁定语义，轮次防止旧请求污染新练习。
3. 分页和匿名练习如何呈现？
   推荐：每页 50 题，顶部/底部沿用 sr-icontool 箭头与页数，整课题号不变；登录进度数据库恢复，匿名仍可本次练习且不复用其他账号缓存。重做沿用整课完成后原按钮。
   理由：保持现有题目和反馈，无新增设计 token；用户要求分页取代原整课同页。记录受管文档旧说明，未经专门授权不改 registry。
   决策：按推荐执行，自行判断；仅使用现有工具按钮、图标与样式，不改受管 registry。
