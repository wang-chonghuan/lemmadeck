# 现状

- `assemble.py` 的 `check_toc()` 只展开 `contents[].lessons[].topics[]`，而 6a 的章末补充
  习题和全书难题是独立的 `kind: exercises` 条目；因此它们即使被装订，也无法取得 TOC
  已定义的正式卡片 ID。
- 课程应用按 TOC card ID 查询 `sr_lessons`，并已支持没有正文、只有练习的卡片；这次无需
  改应用结构。
- 6a 尚无抽取产物和已发布行，首批可从源扫描件建立干净的书级目录。
- 基础课程发布器保留已有答案键但不保留交互规格，所以整条发布链的正确顺序是基础课程、
  答案、交互。

# 路线

1. 为装订器建立覆盖编号 topic、章末练习和全书难题三类 TOC 卡片的统一索引与匹配规则，
   补确定性测试，证明六个纯练习条目都能按现有 ID 认领。
2. 按 6a 的物理页与印刷页偏移准备并逐页转写前两个单元及闭合边界，运行页级 finalize、
   assemble、vectorize 和再次 assemble，修复首批暴露的管线阻断。
3. 只为两个目标 card ID 建立 `modern-us-neutral` edition；按需通过 `ld-s10y-image`
   生成现代图，并通过 adaptation 与离线 render 审计。
4. 先发布基础课程，再为每道题生成、校验并发布答案键和交互规格；查询数据库核对最终对象。
5. 启动本票端口，在桌面和移动视口检查目录、两张课程卡、练习题、插图和一次服务端自动
   判题，同时断言初始浏览器载荷不含期望答案。
