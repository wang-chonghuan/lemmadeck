  decimal-only values in place of the explicitly requested fractions.

  numerator/denominator scope and handles serialization, not arbitrary

  change the source task.
- **Separate numerator and denominator scalar boxes:** fixed expected values
  impose one preferred fraction. Independent per-box equality cannot express
  the relation between freely chosen numerator and denominator or accept all
  valid positive-denominator pairs without a composite predicate.
- **Classification-only exact parts:** the finite classification subtask can
  be deterministic. That does not make the requested full answer auto; it
  leaves the fraction-writing obligation unjudged. Eight neutral classification
  labels would not themselves reveal the selected entries, so disclosure is
  a defect of the proposed five-box design, not of every possible layout.
- **Packing a list/set or a formula into one expression:** scalar expression
  equivalence has no documented contract for exact selected-set completeness,
  all required fraction syntaxes, or integer/positive-denominator constraints.
  A syntax filter, relational fraction validator, list/set judge, or split
  scored/unscored mode would require an additional contract, not merely
  different expected values.

These are contract-level incompatibilities, not newly executed negative
controls. There is no authorized composite judge and none is introduced.
