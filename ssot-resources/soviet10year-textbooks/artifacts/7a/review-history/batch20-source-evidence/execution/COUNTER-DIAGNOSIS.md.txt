not guessed layout coordinates. The line counter uses `line_h=40`,

### Original98 г) Fraction Row

Raw numerator support occupies y1116-1203; the outer rule occupies
x379-700/y1205-1210 (width322/height6/area1155). The denominator digits
occupy y1219-1249, with individual digit heights28-29.

- `_fraction_across_split`, called for a1116/split1219/b1249, correctly
  finds that long outer rule with numerator and denominator support.
- Its glyph filter at `layout.py:178-182` admits a margin speck:
  x1473-1484/y1116-1127, width12/height12/area77. Height12 passes the

  That exceeds the permitted `0.9*36=32.4` baseline distance.
- Consequently the unrelated-glyph rejection at `layout.py:207-213`
  returns false before the final `_single_fraction_row` call.

- Expansion recognizes the numerator-only band as one nested fraction row,
  and the denominator remains another row. Hence the final excess is one.
- Calling `_single_fraction_row` on the full combined band also returns

## Smallest Tested Proposal

`proposed-layout-counter.patch` is an unapplied proposal, not a shared edit:

1. In the existing post-rule residual-component loop, also ignore components
   shorter than `0.6*line_h` for the helper's row-support decision.
2. In `_fraction_across_split`'s glyph-support list, use `0.6*glyph_h`
   instead of `0.3*glyph_h`.

The `0.6` glyph-height standard already appears in the counter's full-row,
standalone-digit and footer support checks. This proposal applies it
consistently to evidence that claims an unrelated full printed row.
It does not change rule detectors, global ink cleanup, crop pixels, gap limits,
join width ratios, expansion pitch, page-number handling or source text.
No page ID, coordinate, expected row total, exercise label or source formula
is hard-coded into the proposed helper logic.

With the in-memory proposal, а)/б) residual support is y860-888 (29 pixels),
and full г) residual support is empty after fraction masking and glyph
qualification. Both helpers now recognize their actual fraction rows.

## Preserved Failed Probes and Limits

The first diagnostic-script attempt failed only while serializing a NumPy
boolean to JSON; no shared or source writes occurred. Subsequent diagnostics
used explicit scalar serialization.

`counter-proposal-results.json` preserves rejected fraction-only crop probes:
such crops remove the ordinary-row height calibration and are not valid
standalone page-counter fixtures. They were not promoted as passing evidence.

`counter-proposal-results-v2.json` preserves an attempted ambiguous helper
negative: two glyph rows fully inside a wide rule's columns can geometrically
represent a single fraction. Both the baseline and proposal helper return
true there, although the line-level counter preserves two rows. This existing
helper ambiguity is recorded separately in v3/v4, not changed into a claim
that the helper can infer prose or math semantics.

The proposal is deliberately narrow. It does not prove all unseen smaller
fonts are safe, and it does not change the page-global height estimator.
Parent review and explicit authorization are still required before applying
shared code or continuing source extraction.
