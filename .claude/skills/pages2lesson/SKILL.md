# pages2lesson

**一条命令，一课入库。**

```bash
P=.claude/skills/ld-s10y-lesson/.venv/bin/python
L=.claude/skills/pages2lesson/tools/p2l.py

$P $L run --book 3m --lesson math3-c1-ex5
```

反复跑**同一条命令**，直到它说 `done`。每次调用它把机械活一路跑到下一个未满足的 gate，
然后把待做的工作写成**若干份自包含 brief**，只打印它们的路径。
你的工作就是：**给每份 brief 派一个全新子代理，然后再跑一次这条命令。**

## 最要紧的一条：派子代理，不要自己做

```
派 2 个**全新**子代理（不要用 fork），各读自己那一份 brief：

  page-0045: .tmp/pages2lesson/3m/math3-c1-ex5/units/page-0045.md
  page-0046: .tmp/pages2lesson/3m/math3-c1-ex5/units/page-0046.md
```

给子代理的提示就一句：**「读 `<brief 路径>` 并照它做完」**。

- **不要**把 brief 的内容复制进你自己的上下文
- **不要**替子代理打开页面图
- **不要**用 `fork` 型子代理——它会继承你的全部上下文，等于没改
- 同一批的单元彼此独立，一条消息里并发派出去

### 为什么

STEMROBIN-191 一课实付 $46–50。本单第一版把管线的来回从几十次压到 5 次，
实测仍然 **218 轮 / 43.6M token / $30.47**。拆开看：

```
cacheRead  42,942,985  (98.5%)   ← 已有上下文 × 轮数
output        167,327            ← 真正写出来的东西
```

**钱不在步骤数上，在「所有工作挂在同一个会话里」这件事上。** 一页 300dpi 的扫描图
进了上下文，之后每一轮都要再付一遍；32KB 的 SKILL.md 同理。
真正不可约的工作只有入 ~28K / 出 ~22K，约 $0.3–0.7。

全新子代理只看到自己那份 brief 和自己那张图，做完把文件写在磁盘上、
把两行结论还回来。页面图不进主会话，brief 也不进——这是这条路径省钱的全部机制。

## 三类单元

驱动按状态自己决定这一轮派什么，你不用记。

| 单元 | 一个子代理做什么 | 产出 |
|---|---|---|
| `page-NNNN` | 读页面图，写带类型的块，跑 `finalize` 自检到绿 | `pages/NNNN/page.md` |
| `edition` | 把课文与题改写成 modern 版，跑 `adapt-finalize` 自检 | `.tmp/.../*.template.json` |
| `figure-<id>` | 写 FigureSpec，渲染，对照原书图做目视验收 | `editions/<ed>/figures/<id>.*` |

每份 brief 都是自包含的：该读哪张图、该写哪个文件、规则、以及**它自己要跑的校验命令**。
子代理在自己那个小上下文里改到绿为止，不把来回带进主会话。

**失败会带着报错回到同一个单元。** 驱动核对不过时，把校验器报出的**全部**不通过项
写进那个单元的 brief 开头，再派一个新的子代理。
同一单元**首发 1 次 + 修复 3 次**，再不过就硬停交给人；
计数落在 `units/<unit>.attempts`，交付成功后清空。
查清原因后删掉那个文件可以重新放行该单元——硬停的报文里会写出确切路径。

**机械失败（`prepare` / `vectorize` / `assemble` / `render` / `publish`）不走单元**：
它们是工具或数据的问题，不是模型写错了，所以直接报给你（exit 1），
大段输出落在 `.tmp/pages2lesson/tool-output/` 下，正文只给一行路径。

## 命令

```bash
$P $L run    --book 3m --lesson math3-c1-ex5      # 跑到下一个 gate
$P $L run    --book 3m --pages 44-47              # 从页码反推卡片
$P $L status --book 3m --lesson math3-c1-ex5      # 只看进度，什么都不改
```

- `--lesson` 与 `--pages` **任给其一就从 TOC 推出另一个，两个都给就互相校验**。
  推荐 `--lesson`：页码范围由目录决定，**自动包含收口页**。
  `--pages` 单给时，范围必须**从某张卡的首页开始**——驱动取那张卡，
  范围里被收口页带出来的下一张卡不发布。
- `--no-publish`：做到发布预检就停（**这是终点，不是 gate**），真实入库的命令会打出来给你。
- `--edition-ready`：现代版确实一字不改时，跳过「已改写」判据。
- `--force-prepare`：重建 `.tmp` 里的页渲染**和现代版模板**（会丢掉模板上已有的改写）。
- `--json`：只输出结构化报告。报告落在
  `.tmp/pages2lesson/<book>/<card>/report.json`（`status` 子命令写同目录的 `status.json`）。

退出码：`0` 已交付，或 `--no-publish` 下预检通过 / `3` 停在 gate（brief 已写好）/
`1` 本阶段有失败 / `2` 硬停（需要人决定）。

## 收口页：这条检查是本技能存在的另一半理由

**小节边界常落在印刷页中间。** TOC 说这张卡起于印刷页 40、下一张起于 43，
那么 40–42 属于这张卡——而只有把 **43 也转写出来**，才知道第 42 页之后没有本卡的内容了。

43 没转写时，装订照样产出一课、题号连续性照样过（本卡自己的题号没缺）、
页级行数对账也照样全绿（它只看单页）。于是一课少几道题是**静默**的：
这已经连续让三课漏题。`math3-c1-ex5` 实测——这条检查逼着把印刷页 43 转写出来，
那一页正好带出题 20–23，**当场救回 4 道题**。

所以 `--lesson` 推出的页码范围**包含下一张卡的首页**，`assemble` 的 audit 里有
`unclosed_cards`；驱动把本次交付那张卡的 `unclosed_card` 当**硬失败**，
带着它不允许入库。只发布本卡，边界页带出来的下一节不发布。

## 两件实测过的事，别再踩

**裁图框先看候选，对不上就手画。** `prepare` 把候选区域画在 `page.regions.png` 上并
编了号，块头写 `region r3` 认领，一张表被拆成两个候选时写 `region r2+r3`。
但实测（3m 印刷页 40–43）**两张图一个都没认领成**：靠留白分组的竖式阵列根本没被提出来、
被细网格线切碎的方格条只提出左半截，反而把背面透印的竖条和纸边污点提成了候选。
判据是**对得上就认领，对不上直接 `box x,y,w,h`，不要为了用 region 去凑**。

**标签位置不用算。** 写 `labelPlacement.position` 当首选就行。渲染器自己错位（八个方位）、
错开（gap ×1/1.5/2.25/3）、扩画布（边距 8%/16%/25%，且只在实测字号仍 ≥ `minTextPx`
时接受），解不开才失败并报出它试过哪些布局。

## 纪律

- **零付费图像调用。** 驱动遇到 `mode: generated`（Azure gpt-image-2）直接硬停并报告。
- **不动别的课，但要看清这条防线的边界。** `assemble` 是全书重算。驱动在装订前后各取
  一次 `git status --porcelain -uall`，只处理「之前干净、之后脏」的文件——
  别人正在改的东西不碰。其中：
  - 别的课 `lessons/<other>/` 或 `editions/*/lessons/<other>/` 下**已跟踪**文件被改动
    → `git checkout --` 还原并记进报告；
  - **新建**的文件还原不回去（git 不认识它），所以只报告、不删。
    这不是边角情况：收口页属于下一张卡，装订**每课都必然**为它产出一个新的 lesson
    目录（3m 实测产出了 `x7-多位数的加法和减法`，带 4 道题）。它会跟着这次交付进 commit，
    **怎么处置要人决定**，驱动只负责让你看见。
  - `figures/`、`pages/`、`book.json` 不在这条防线内（它们本来就是全书共享的）。

  已发布课程另有 rebind 防线：`assemble` 发现重算结果与已发布 edition 的
  `source.sha256` 不符时，保留该课全部原文件并报错，只有 `--allow-rebind` 才放行
  （驱动从不传它）。
- **对账按本次交付的那张卡作用域。** `assemble` 的退出码带着全书的既有失败，
  判据取 `book.json` 的 audit，只有提到本卡的才拦。
- **python 用 `ld-s10y-lesson/.venv`。** 本技能不自带环境、不装依赖。
- **预检不是终点。** 驱动自己先跑一次 `publish --dry`，通过后默认真实写库；
  只有 `--no-publish` 会停在预检，那时入库命令由人执行。生成了文件、
  或只跑过预检，都不算这一课交付了。
- **装订必须真的跑完才算。** `book.json` 是 `assemble` 最后一步才写的，
  它中途抛异常时磁盘上留着上一次的 audit。驱动用输出里的 `[assemble]` 完成标记判断，
  没有标记就是失败——否则会把一个没把新转写页算进去的旧 lesson 发布出去。

## 和 `ld-s10y-lesson` 的关系

`ld-s10y-lesson` 仍然是逐 cap 的入口，**没有被删除、改名或改动对外命令**；
需要只跑某一个 cap、或处理驱动没覆盖的情形（整章生成、选择题接入、答案键）时用它。
pages2lesson 是它之上的驱动，共用同一套工具、同一套产物目录和同一个发布器。
内容规则也以它和 `ld-s10y-image` 的 SKILL.md 为准——brief 里给的是写一个单元够用的部分，
不够时 brief 会点明去读哪一节。
